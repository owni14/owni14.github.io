# 직접 작성하는 한국어·영어 글

자동 번역 없이 작성한 언어별 글만 표시한다. 한국어 주소는 기존 `/`, `/posts/...`, 영어 주소는 `/en`, `/en/posts/...`를 사용한다.

## 글 작성

같은 글의 한국어·영어 파일은 분류와 파일명을 같게 둔다.

- 한국어: `content/posts/web/javascript/promise.mdx`
- 영어: `content/translations/en/web/javascript/promise.mdx`

각 파일에 해당 언어의 제목·설명·본문을 직접 작성한다.

```mdx
---
title: Understanding promises
description: How promises work in JavaScript.
date: 2026-11-24
---

English content goes here.
```

기존 글은 수정하지 않고 영어 파일만 추가하면 자동으로 짝이 연결된다. 한국어 원문이 없는 영어 글도 영어 폴더에 바로 작성할 수 있다. 별도의 한국어 버전을 관리해야 하면 `content/translations/ko/<category>/<subcategory>/<slug>.mdx`를 사용할 수도 있다.

## 화면 동작

- 홈·메뉴는 헤더 EN/KO 버튼으로 전환한다.
- 글에서는 다른 언어의 공개 글이 있으면 같은 글로 전환한다. 짝이 없어도 언어 토글은 사용할 수 있으며 선택한 언어의 글 목록으로 이동한다.
- 언어별 목록·검색·분류·RSS·사이트맵에는 그 언어로 작성된 글만 나온다. 미작성 영어 페이지나 ‘번역 준비 중’ 안내는 만들지 않는다.
- 한국어 원문이 초안이면 연결된 영어 글도 공개되지 않는다. 영어 파일 자체의 `draft: true`도 존중한다. 영어 단독 글은 자체 공개 상태를 따른다.
- 각 글의 canonical과 hreflang은 실제 존재하는 언어 버전만 가리킨다.

소개·경력은 `content/site.yml`, `content/site.en.yml`, 공통 화면 문구는 `src/lib/i18n.ts`에서 관리한다. 현재 영어 글은 예시로 직접 번역한 「블로그 재시작」 1개다. 기존 글의 원문은 그대로 보존했다.

## 검증

`pnpm dev`로 두 언어를 확인한다. `pnpm typecheck`, `pnpm lint`로 검사하고, 운영 배포는 기존 `pnpm build`를 사용한다. 현재 실행 환경은 기본 Turbopack 빌드의 포트 사용을 제한하므로 로컬 정적 검증은 `pnpm exec next build --webpack` 후 `node scripts/generate-legacy-redirects.mjs`로 진행했다.

한글 slug는 조회 시 한 번 디코딩하고 NFC로 정규화한다. 개발 중에는 정적 내보내기 검증을 끄고 운영 빌드에서만 적용한다.

배포는 기존 GitHub Actions 흐름을 사용한다.
